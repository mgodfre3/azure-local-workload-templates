# Support matrix and public implementation references

Documentation reviewed: 2026-11-19. Vendor support evolves; verify the current requirements for the actual stamp release before deploying. Partial pilot evidence is not complete live acceptance or production certification.

Windows Server 2025 is an explicit **existing-image** alternative for Windows profiles; Windows Server 2022 remains the default and the only automated Marketplace import. The guest guard accepts server builds 20348 and 26100 and rejects workstation editions. Microsoft lists Windows Server 2025 Datacenter: Azure Edition in the [SQL Server 2022 OS support matrix](https://learn.microsoft.com/sql/sql-server/install/hardware-and-software-requirements-for-installing-sql-server-2022#operating-system-support). This is an offline-tested compatibility boundary, not evidence that any particular image, SMB/IIS/SQL service or monitoring enrollment has passed live acceptance.

Ubuntu 24.04 is the primary custom-image choice for Nginx and base Linux; 22.04 remains an explicit compatibility option. The launcher retains normal preparation attestation/import checks; the separate, explicitly enabled existing-image pilot path records unknown provenance and never substitutes `preparedImageConfirmed: true`. Both Linux profiles fail guest acceptance unless the requested release, NoCloud/cloud-init, requested SSH identity and password-disabled login are observed. Guest checks cannot prove source-image trust or complete generalization. NoCloud metadata being null is inconclusive; successful provisioning and guest acceptance are distinct evidence.

SQL 2022 supports Developer/Evaluation and licensed Standard/Enterprise. Microsoft's [Setup PID parameter](https://learn.microsoft.com/sql/database-engine/install-windows/install-sql-server-from-the-command-prompt?view=sql-server-ver16#installation-parameters) determines the edition from the product key; this project does not publish paid keys or infer license entitlement. Matching actual edition is checked after installation, including rejecting Enterprise Evaluation for Enterprise. Paid keys are retrieved **inside the guest** using [Arc managed identity challenge authentication](https://learn.microsoft.com/azure/azure-arc/servers/managed-identity-authentication) and a version-pinned Key Vault secret. Supply secret-get access at the individual secret scope externally; no automatic role assignments or vault networking changes occur. A temporary ACL-restricted [Setup configuration file](https://learn.microsoft.com/sql/database-engine/install-windows/install-sql-server-using-a-configuration-file?view=sql-server-ver16) keeps the PID out of the extension/Setup process command and ARM state. Microsoft documents that the [generated configuration file excludes PID](https://learn.microsoft.com/sql/database-engine/install-windows/view-and-read-sql-server-setup-log-files?view=sql-server-ver16#the-configurationfileini-file); native installer diagnostics remain sensitive and must not be published unreviewed. A key does not replace legal license confirmation, explicit terms acceptance, matching full Microsoft-signed ISO media or SHA256 verification. Paid installation is not live-certified by the offline suite.

The [Azure Local Marketplace image documentation](https://learn.microsoft.com/azure/azure-local/manage/virtual-machine-image-azure-marketplace) explicitly lists `microsoftsqlserver/sql2022-ws2022/enterprise-gen2`. The separate `sqlServer.installationMode: "marketplace"` path validates the target stamp's EdgeMarketplace catalog and concrete version before a missing-image import. This offer can be Preview. Catalog `legalTermsType: None` and a successful download do not prove licensing entitlement; SQL Enterprise/Windows licensing and applicable terms must be independently confirmed before VM deployment. This mode does not accept a PID or reinstall SQL: it verifies default service, actual Enterprise major16, Windows authentication and online databases, preserving image paths and RAW extra disks without firewall changes. Client/admin acceptance and any activation workflow remain separate prerequisites, not an implied Azure IaaS SQL plan/extension flow.

Windows Firewall can return a configured CIDR as `network/dotted-subnet-mask`. The guest firewall guard accepts that representation only when the mask is contiguous, non-universal and fully contained within `allowedCidrs`. Answer-file CIDRs remain canonical prefix-length notation; normalization does not authorize broader rules or automatic narrowing of inherited rules.

For Linux diagnosis, [cloud-init exit code 2](https://docs.cloud-init.io/en/latest/explanation/return_codes.html) means recoverable/degraded errors, not necessarily a crash. Strict acceptance remains the default. Explicit `linuxProvisioning.schemaPolicy: azureLocalKnownWarnings` verifies only the exact investigated provider permission/raw signature and matching runtime network annotations, retains original error paths and hashes, and requires completed phases with zero actual module/final errors. Unknown warnings and unsafe resulting file state still fail; see the README for its complete boundary. Separate source-image identity/preparation defects from provider-generated NoCloud/network schema warnings. The stable VM template submits `linuxConfiguration`/SSH settings, not cloud-config `customData`; its subsequent Custom Script payload is independently LF-normalized/base64-encoded. Validate the actual generated cloud-config using the guest's installed cloud-init schema without printing user-data or tokens. Inactive `ssh.service` alone is not proof of inaccessible SSH on socket-activated Ubuntu. After the selected cloud-init policy and key/password-lock checks, acceptance may start the socket-backed service with a bounded wait **only if `ssh.socket` is already active**, then validates effective password-disabled SSH settings; it does not enable a closed endpoint or rewrite SSH configuration. Do not regenerate an enrolled guest's machine identity or clean cloud-init state as an automatic repair.

Windows OS logs use the standard `Microsoft-Event` input/data-flow stream and the workspace's `Event` table, as documented in the [Azure Monitor DCR sample](https://learn.microsoft.com/azure/azure-monitor/data-collection/data-collection-rule-samples#windows-events). `Microsoft-WindowsEvent` targets a different table and must not be substituted; a workspace without that table rejects the DCR with `InvalidOutputTable`. Do not create a different destination table to mask an incorrect stream name.

The existing Log Analytics workspace can be in another region in the same subscription. Each new DCR derives its location from that workspace, while AMA stays in the VM region; the existing destination and its resource group are not relocated. This follows the [Azure Monitor DCR region requirement](https://learn.microsoft.com/azure/azure-monitor/vm/data-collection#create-data-collection-rule-dcr). Private Link/AMPLS remains outside this implementation.

## Required live acceptance before releasing production support

In an explicitly authorized disposable environment: run each of the six profiles separately, then together with counts greater than one; exercise DHCP and per-instance static IPs; prove Marketplace and digest-based custom image reuse plus missing Windows/CSV/blob image imports; verify expired/unreachable source failures and timeout behavior; confirm clean guest onboarding, safe disk identity, extension readiness and local/client service access; verify base-profile disks stay RAW and no application is claimed; rerun and increase/decrease counts without renaming or deleting existing resources; inject a guest failure and inspect partial state; verify AMA heartbeat and OS logs in the actual workspace. Test scoped IIS/firewall and Nginx HTTP denials from a second client. Confirm Windows and SQL licensing, actual OS-disk sizes and backup/restore separately. None of these live acceptance checks has been performed by the offline suite.

The stable VM schema has no image-based OS disk size override. `suggestedOsDiskSizeGB` is explicitly advisory; the launcher only applies CPU, RAM and data-disk sizes, and does not perform OS-disk resizing. CSV input is intentionally narrower than general share-path syntax: only stamp cluster shared volume VHDX paths are accepted. Blob import supports Azure public-cloud Storage page blobs using read-only SAS tokens supplied at runtime, not credentials in answer files. The digest tag records the operator's attestation, not a checksum independently verified by the provider.

Do not silently expand the image allowlist or use generic Azure IaaS URNs. If a desired guest image cannot use supported zero-touch Arc onboarding, stop and document the preparation gap rather than presenting an empty VM as a configured workload.
